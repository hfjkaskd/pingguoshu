# 飞钱动画测试模块

测试场景：`Assets/FlyMoneyLab/Scenes/FlyMoneyLab.unity`

在 Unity 中打开场景并进入 Play Mode，点击底部“播放”。也可以使用菜单 `Tools > Fly Money Lab > Open Test Scene`。

本模块独立运行，不主动初始化 SDK、不播放广告、不修改游戏存档。顶部数字仅为测试计数。当前项目自身注册的全局启动逻辑（例如统计模块）仍由原项目控制。

## GM

- BR / ID / US：切换已有的粉色、蓝色、绿色纸币与钱束。
- 自定义：在场景根对象 `Fly Money Lab` 的 Inspector 中设置 `Custom Paper`、`Custom Bundle` 和 `Custom Trail Color`，然后进入 Play Mode 选择“自定义”。图片需要导入为 Sprite。
- 标准 / 低配：32 + 28 或 20 + 20 个粒子，分别允许最多 2 / 1 组同时播放。
- 数量、时长、散开半径、飞行图片大小：影响下一次播放，正在播放的参数保持独立快照。
- 下落速度：控制钱束飞向目标前的持续下落，默认 48，范围 0～120。可先试 30 / 48 / 70，0 表示同时关闭下落、横向飘移和摆角；调整后从下一次播放生效。Inspector 对应 `Settings > Fall Speed`。
- 长拖尾、循环播放、三个目标位置、暂停/继续、清空。
- 开场音效：即时静音或开启，默认使用项目现有 `SFX_DollarExplosion.mp3`。场景根对象的 `Burst Sound` 可更换 AudioClip，`Sound Volume` 可在进入 Play Mode 前调整音量。
- 逐帧进度：暂停后定位到指定动画进度，使用固定随机种子便于对照视频。
- 突发 10 次：验证并发限制；超过上限的请求会被拒绝，不进入等待队列。
- 目标销毁测试：播放后销毁一个临时目标，验证中断及回收，正式测试目标仍可继续使用。
- GM 内容可上下滚动。竖屏默认收起，点击底部 GM 展开。

## 文件职责

- `Runtime/FlyMoneySettings.cs`：参数、硬上限和输入校验。
- `Runtime/FlyMoneySimulation.cs`：以绝对时间采样的确定性轨迹，包含开场弹射、撒钱、钱束持续下落、连续转向和错峰飞行。
- `Runtime/FlyMoneyGraphic.cs`：原生 UGUI 网格批量绘制，包含 Sprite 原始 UV、开场卡通云团/短亮线/星芒和渐隐带状拖尾。
- `Runtime/FlyMoneyPlayer.cs`：固定两个播放槽、资源缓存、单音源播放、暂停与中断、生命周期和完成通知。
- `Demo/FlyMoneyLabScene.cs`：测试界面、响应式布局和原生 UGUI GM。
- `Editor/FlyMoneyLabEditor.cs`：场景菜单和自动检查。

三个程序集只依赖 Unity 原生模块与彼此；不依赖 DOTween、UniTask、Odin、UI 粒子插件或广告 SDK。

## 性能边界

每个 Player 预建 2 个播放槽，每槽 3 个绘制对象。粒子数据容量固定，每层硬上限 64 个，拖尾最多 8 段。默认标准档远低于这些硬上限。不同纹理分层绘制，不强制修改现有图集，也不在运行时复制图片。

开场以一小团圆润的卡通云“噗”地弹出，中心云团先膨胀回弹，再分成 4 小团散开缩小，默认约 0.32 秒内消失，衔接纸币飘落与收集。点缀缩减为 6 道短亮线与 5 颗小星芒，扩散半径由 210 缩至 102 个参考单位；背景散钞的弹射和飘落保持不变。改变总时长会同比缩放这些时序。

收集钱束弹出散开的同时叠加缓慢下落，散开完成后持续下落，直到轮到自己沿弧线转向目标，不再有静止等待和临起飞时突然下沉。纵向带轻微重力加速度，横向保留少量散开惯性，并叠加不同相位、频率的小幅飘摆与摆角，避免整齐匀速地垂直滑动。钱束保持自身大小，不做持续缩放或大幅翻滚。

飞行从实时下落的位置和角度接出，位置与角度的速度、加速度均延续到转向曲线，再逐渐加速收集。入口运动状态在启动时缓存，拖尾采样直接复用，避免每段拖尾重复计算飘摆。拖尾只在转向飞行阶段生成。保持原有错峰出发及完成时刻，不增加对象或物理模拟。

`fallSpeed` 是默认总时长 1.7 秒下的基准下落速度，各钱束按相位取 0.82～1.18 倍系数，再乘现有空间比例；实际速度随下落过程逐渐增加。默认横向飘摆幅度约 2.5～5 个参考单位，摆角幅度约 2～4 度，各钱束节奏不同。改变 GM 总时长会同比缩放时间轴，Canvas 缩放也会改变实际屏幕像素速度。它控制持续下落，不再是固定下沉距离或独立的 0.12 秒下沉阶段。

云团、短亮线、星芒与拖尾共用原有白纹理绘制层，每槽最多额外 506 个顶点，不新增绘制对象、纹理、材质或第三方插件。圆弧云轮廓仅初始化时计算并缓存，绘制时复用；关闭拖尾仍保留完整开场效果。

音效在界面初始化时通过 `PrepareSound` 准备。每个 Player 最多创建 1 个原生 2D AudioSource，使用 `Play` 而非叠加 `PlayOneShot`，播放中不重启，并设 0.12 秒最小触发间隔。仅受理成功的请求触发声音；缺少音频、未加载成功时仍可正常播放动画。暂停/后台同步暂停声音，清空、禁用、最后一组结束时停止，拖动逐帧进度静音且不会重放。不会修改共享音频导入设置或卸载其他模块使用的音频。生产接入应将 `SoundEnabled` / `SoundVolume` 与游戏已有音效设置同步，并使用场景原有 AudioListener。

Sprite 的顶点、UV、三角形数据只在准备或首次使用时读取并缓存；支持普通 Sprite 及保留原始网格/UV 的图集 Sprite。单张 Sprite 限制为 256 顶点、1536 索引，异常或过于复杂的网格会拒绝播放，避免超出 UGUI 网格上限。

建议在界面初始化时调用 `PrepareSprite`。第一次图形绘制仍可能涉及 Unity 内部网格缓存和材质预热，性能采样应区分首次播放与稳定播放。

GM 可见时每半秒更新统计文字，会产生少量测试界面的字符串分配；收起 GM 后停止这部分统计。核心标记为 `FlyMoney.Update`。低端设备仍需在 Android/iOS 真机上检查 CPU/GPU 帧时间、首次广告返回和长时间重复播放；桌面测试不能代替真机验收。

## 接入约定

```csharp
// player 挂在独立、非交互的子 Canvas 上。
player.PrepareSprite(paperSprite);
player.PrepareSprite(bundleSprite);
player.PrepareSound(openingClip); // Optional; call during setup.
player.SoundEnabled = true;
player.SoundVolume = 0.65f;
bool accepted = player.TryPlayFromTransforms(
    paperSprite, bundleSprite, startTransform, targetTransform,
    FlyMoneySettings.Standard, 37u, OnAnimationFinished);
```

`TryPlay` / `TryPlayFromTransforms` 返回 false 表示请求未受理，不调用完成回调；返回 true 后，完成或中断只通知一次。拒绝、中断都应由业务层按既有规则处理奖励，本模块不负责发奖。

`TryPlay` 的起终点是 Player 所在 RectTransform 的本地坐标。`TryPlayFromTransforms` 会转换 UI 坐标，并监测目标销毁。飞行目标位置在启动时确定；布局切换时应中断并重新触发。

`StopAll`、组件禁用、目标销毁分别返回 `Stopped`、`Disabled`、`TargetLost`。正常结束返回 `Completed`。切后台暂停计时，恢复时跳过第一帧的时间增量。完成通知前先释放播放槽，支持回调中再次播放；`StopAll` 清理期间不接受新请求。

## 自动检查

Unity 菜单：`Tools > Fly Money Lab > Run Self Checks`。

检查包含参数边界、确定性轨迹、开场向外弹射/云团分散淡出时序、紧凑范围与云网格顶点上限、连续加速下落/横向飘移与摆角边界/转向位置及速度和角速度连续性/错峰及总时长、单音源复用与音量校验、空资源、目标销毁、暂停、并发上限、回调重入、1000 次重复启停及核心分配采样。收集动作覆盖标准档、低配档、1/64 个钱束、最短/最长时长和下落速度 0/48/120。报告写入项目的 `Library/FlyMoneyLab/checks.json`。编辑器自检不播放音频，实际发声需在 Play Mode 或构建后测试。

没有将此场景加入原有 Build Settings。正式奖励流程已通过框架适配层接入，免费领取默认继续使用旧动画。

## 正式框架接入

- `VFXUtils.PlayItemCollectFx` 保留原调用形式，新增 `animation` 参数，默认 `RewardCollectAnimation.Legacy`。明确的广告奖励使用 `BurstCollect`；不根据 `isAd` 或货币种类猜测来源。
- `RewardItemCollectFlow` 由 `UIModule` 初始化，使用现有奖励层和相机，不引入测试 GM、Camera、EventSystem 或 AudioListener。新旧动画共用并发和触发频率预算，超限直接结束表现，不无限排队。
- 广告 `PlayCurrentFly` 事件由框架常驻流程接收，不再依赖 `CurrencyBar.OnEnable`。普通广告到账、已有双倍广告领取和广告老虎机领取选择新版；免费点击领取、免费老虎机及其他未指定入口保留旧版。
- `ItemUtils.AddItem` 先修改并保存本地数量，再播放动画。`addFinishAction` 现在是表现完成后的界面通知，不负责发奖；首张到达时触发，中断或无法播放时走统一收尾。SDK 服务器收益请求和金额计算没有改动。
- 广告批次 ID 与物品类型组成去重标识，金额和标识存入同一份 `ItemSaveData`。保留最近 256 条物品收据，覆盖近期重复回调及重启重放；这不是无限历史去重，也不替代服务器的幂等结算。
- `AddItemParam.callbackOwner` 可指定界面回调归属。省略时尝试使用回调目标组件或显式飞行目标；捕获页面的 lambda 应显式传入所属组件，避免依赖编译器闭包推断。
- 页面关闭、隐藏后复用、切场景、分辨率变化会使旧表现失效；已保存奖励不回退，失效页面的回调不再执行。后台暂停声音和计时；缺失图片、目标、音效按降级路径处理。单个表现最多占用 8 秒前台时间，超时统一回收，避免预算长期被占用。
- 新版参数及回退开关位于 `Assets/BizzaWZ/Final/BizzaGame/Resources/Bizza/ChannelConfig/RewardItemCollectFxConfig/RewardItemFlyConfig.asset`。`useNativeAdRewardFx` 关闭后广告效果回退旧版，`forceLowNativeQuality` 强制低配；移动设备内存不高于 3 GB 时默认采用低配，总并发 1，标准档总并发 2。旧版视觉参数保持原值。
- 图片和开场音效集中在 `Assets/BizzaWZ/Final/BizzaGame/Resources/Bizza/RewardFlyResources.asset`。BR/ID/US 复用原项目 Sprite，不复制图片；声音同步 `SoundManager` 的音效静音和音量。
- 在正式场景 Play Mode 中选中 `RewardItemFlyConfig.asset`，展开调试，选择动画类型，再点“仅预览动画（不加钱）”。“中断全部飞钱（奖励不回退）”用于检查收尾。“快速加钱”仍会修改测试中的游戏存档，不要与纯预览混用。

### 中文参数与国家拖尾

在 `RewardItemFlyConfig.asset` 中展开“新版广告奖励”：

- “标准档参数 / 低配档参数”使用中文标签。“飞向目标数量”对应 `flyCount`；“散落图片数量”对应 `rainCount`。数量按每组动画计算，金币与钞票同时播放时各算一组。
- “国家拖尾”可分别设置美国、印尼、巴西的“钞票拖尾”和“金币拖尾”。支持跟随通用颜色、巴西粉色、印尼蓝色、美国绿色、金币金色、自定义颜色和关闭拖尾。默认钞票依次为绿、蓝、粉，金币均为金色。
- 选择只改变配色，不改变该国家的图片。单货币模式中显示为钞票的金币也使用“钞票拖尾”；普通金币和其他物品使用“金币拖尾”。未知国家与图片选择一致，回退巴西设置。
- 国家配置控制 RGB；透明度仍由当前画质档“通用拖尾颜色”的 A 值控制。宽度、长度、分段数也继续使用当前画质档，低配不会被国家配色覆盖。
- 关闭“按国家选择拖尾配色”，全部使用当前画质档的“通用拖尾颜色”；关闭画质档的“启用拖尾”，国家选择不会重新开启拖尾。
- 改动从下一组动画生效，不改正在播放的参数快照，不影响奖励金额或免费领取的旧动画。国家选择只在开始播放时解析，不增加绘制对象、材质、贴图或每帧查询。
- Unity 菜单 `Tools > Fly Money Lab > Check Country Trail Settings` 可检查国家配色、独立金币设置、低配、关闭选项、参数序列化及中文字段映射；不修改配置资产或存档。
- 本轮通过 48 项配置检查及隔离 Windows Player 的 13 类场景、1049 项运行断言。实际渲染检查覆盖三国默认拖尾，以及美国钞票改用蓝色、金币改用粉色；测试报告位于 `Library/RewardFlyValidation/Reports/CountryTrails`，并非完整广告 SDK 或手机真机验收。

进程被系统强制结束时不能保证执行任何回调。恢复依靠动画前的存档和服务器账户数据，而非退出回调；存储失败、网络收益确认之前的退出仍属于业务恢复问题，不能由动画模块保证。
