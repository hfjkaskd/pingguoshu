远端配置路径与下载流程

这套系统的核心行为是“一次性 AB 分组 + 下载一个分组二进制包 + 本地缓存复用”。本报告把远端文件如何组织、运行时如何拼接 URL、什么时候请求、什么时候使用缓存和 Default 回退集中列出。

报告基于当前工作区代码与资源 未修改 Assets 源码与资源 当前为公共模式
结论 当前配置 路径索引 路径计算器 下载流程 边界与现状 优化建议

一页结论

先确定系统定位，再决定如何优化

它不是持续同步器，而是“分组选择器 + 单文件下载器”

首次没有有效分组记录时，运行时先请求 Common/group.bytes（国家模式下为 {Country}/group.bytes），解密并解析权重，随机选出一个 UserGroupName。选中 Default 时读取包内本地文件；选中其它组时只请求对应的 Common/gamedata/{GroupName}.bytes 或国家目录文件。成功后写入 PlayerPrefs 和沙盒缓存，后续启动直接复用。

当前工程里没有找到业务代码真正解析并消费远端关卡二进制；RemoteSystem 目前主要完成拉取、缓存、状态记录和对外暴露字节接口。

配置开关如何决定路径

Group 开关只影响策略，Level 开关只影响非 Default 关卡

CountryGroupEnabled决定策略使用 Common/group.bytes 还是 {Country}/group.bytes。
CountryLevelEnabled决定非 Default 关卡使用 Common/gamedata/{Group}.bytes 还是国家目录。
CountryType=具体国家例如 US，国家前缀为 /US/。
CountryType=None如果任意国家开关开启，则不请求远端，直接走本地 Default；如果两个开关都关闭，则仍走公共远端并正常随机。

例：US + 两个开关都开启

策略：{Root}/US/group.bytes

关卡：{Root}/US/gamedata/group1.bytes

Default 仍然读取唯一的本地 Default.bytes，不下载 US 版 Default。

当前结果

完整下载流程

从 Loading 任务到最终缓存

1
进入 Loading

BIZZA_REMOTEGROUPDATA 开启时，GameMode_Loading 添加 InitRemoteGroupDataTask。

加载本地元配置

读取 Resources/RemoteGroupRuntimeConfig.bytes，解密后得到 URL、超时、重试和国家开关。

2
国家判断

国家开关开启时等待 AccountModule 用户数据；国家为 None 时直接本地 Default。

已有正式记录？

完成标记存在且缓存校验成功，就跳过远端策略和关卡下载。

3
GET 分组策略

公共模式请求 Common/group.bytes；国家模式请求 {Country}/group.bytes。超时 5 秒，RetryTimes=2 时最多尝试 3 次。

解析与随机

RGCFG1 解密 → Base64 → RGSB → 校验版本/数量/权重 → UnityEngine.Random 按权重选择分组。

4
选中 Default

读取包内 StreamingAssets/RemoteGroup/Default.bytes，不请求远端 Default。

选中其它组

公共模式请求 Common/gamedata/{UserGroupName}.bytes，国家模式请求 {Country}/gamedata/{UserGroupName}.bytes，只下载当前随机命中的一组。

5
成功提交

校验非空；远端包写入 tmp、替换目标、回读；然后写 PlayerPrefs 和会话内存。

任意步骤失败

本次尝试本地 Default，不写正式完成标记，下次启动继续允许重试；如果 Default 也失败，外层任务仍会记录日志并结束。

文件内容格式索引

路径正确还不够，文件内容也必须符合当前实现

group.bytes

  1. 外层文本以 RGCFG1: 开头。
  2. 解密后是 Base64 文本。
  3. Base64 解码后以 RGSB 开头。
  4. 包含版本号、分组数量、分组名和 Float 权重。
  5. 权重小于等于 0 的项不会进入随机选择。

gamedata/{GroupName}.bytes

  1. 运行时当前只校验文件非空。
  2. 编辑器预览器可以识别 RGPK 包头。
  3. 运行时不会解析 RGPK，也不会自动注册关卡。
  4. 分组名必须与策略中的 UserGroupName 和文件名完全对应。

当前实现的边界与容易误解的地方

这些不是文档建议，而是当前代码的实际行为

不会下载全部分组
策略中即使有 Default、group1、group2、group3，运行时也只会随机选中一个用户组，并下载该组的一个 gamedata 文件。
不会下载远端 Default.bytes
Default 始终是包内本地回退文件，路径固定为 Assets/StreamingAssets/RemoteGroup/Default.bytes。
策略缓存当前没有参与正常复用
代码会把远端 group.bytes 写入 persistentDataPath/RemoteGroup/group.bytes，但正常启动的复用判断主要依赖 PlayerPrefs 和所选分组的 gamedata 缓存。
商业化配置导出不等于商业化运行时拉取
ChannelABConfig 可以导出 commercial 目录下的 CHAB 文件，但 InitRemoteGroupDataTask 不负责请求和解析这些文件；它们属于独立链路。
当前没有找到远端关卡字节的玩法消费方
在当前工程搜索范围内，TryGetCurrentGameDataBytes 主要被 RemoteSystem 编辑器工具调用；运行时业务目前能明确看到的消费是 UserGroup 埋点，而不是关卡二进制解析。

面向优化的建议排序

这里只给方向，不在本报告中修改代码

P0
统一资源目录并补齐 Default
明确 Assets/RemoteData、RemoteUpload、StreamingAssets 和 persistentDataPath 的职责；确保 Default.bytes 在构建包内真实存在。
P0
明确二进制最终消费者
如果远端关卡配置要影响玩法，需要指定业务解析器和注册入口；目前 RemoteSystem 只负责传递原始 bytes。
P1
缓存绑定国家、版本和配置签名
避免国家切换、远端根地址变化或配置更新后继续复用旧分组和旧 gamedata。
P1
增加 RGPK / checksum / 签名校验
当前关卡文件只检查非空；错误文件也可能被正式缓存。
P1
决定策略缓存是删除还是启用
现在 group.bytes 会写入沙盒但不参与正常策略复用，属于未闭环缓存。
P2
改善弱网和测试体验
增加退避、取消、下载进度、缓存清理和编辑器发布前全量路径预检。
