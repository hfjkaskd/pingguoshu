结论先行：客户端没有自己读取公网 IP 并做黑白名单判断。客户端把设备、地区、运营商、VPN、Token 等信号提交给远端 Worker，由服务端返回 allow 决定是否允许继续加载。

当前最关键现象

ProjectSettings.asset 的 Android 定义包含 BIZZA_IPINTERCEPT 和 BIZZA_REAL_WITHDRAW，但也包含 DEBUG_MODE；而 GameMode_Loading.cs 只有在 BIZZA_IPINTERCEPT && BIZZA_REAL_WITHDRAW && !DEBUG_MODE 成立时才会添加 new IPCheckTask()。因此当前 Android 包会编译相关脚本，但启动加载流程不会挂上 IP 拦截任务。

一、实际运行流程

1加载阶段注册任务GameMode_Loading 初始化 LoadingProcedure。只有宏条件满足，才添加 IPCheckTask。
2等待公共 SDK 配置IPCheckTask 等待 LoadTables 和 WKY_SDK，确保 ChannelConfig.bytes 已加载并完成公共 DeviceInfoUtil 初始化。
3采集设备信号Android 走 Java DeviceUtils；编辑器可使用 AuthConfig 中的模拟字段。
4POST 授权请求向 WorkerUrl 发送 appId、包名、设备 JSON、旧 Token、Play Integrity Token。
5服务端决定能否继续allow=true 继续加载；否则弹窗、退出并抛出 TokenClientBlockedException。
allow=true
如果返回新 Token，写入 PlayerPrefs 的 AUTH_TOKEN，加载流程继续。
allow=false
清理本地 Token，按原因显示本地化提示，非编辑器调用 Application.Quit()，随后抛异常阻止加载。
网络/解析失败
转成 SERVER_ERROR，走默认失败提示；外层加载器还会进入通用网络错误兜底。

五、当前代码中的风险与异常现象

高：当前 Android 构建不会进入 IPCheckTaskAndroid 定义含 DEBUG_MODE，入口条件显式使用 !DEBUG_MODE。因此日志里看不到“令牌客户端”日志，不代表 Worker 放行，而是客户端根本没有发起授权请求。
高：IPCheckTask 与 ChannelConfig 加载存在时序风险IPCheckTask 只依赖 LoadTables；ChannelConfig.bytes 却在 WKY_SDKTask 中加载，而 WKY_SDKTask 也依赖 LoadTables/LoadGameData。LoadingProcedure 会并行执行同批次任务，IPCheckTask 可能先访问 ChannelConfig.Instance.AppId，导致空引用或被外层归类成 SERVER_ERROR。建议让 IPCheckTask 显式依赖 WKY_SDK，或把 ChannelConfig 提前初始化。
中：Play Integrity 尚未接入GeneratePlayIntegrityToken() 固定返回空字符串。如果 Worker 要求完整性 Token，服务端会返回 APP_INTEGRITY，这是当前代码路径下的预期拒绝结果。
中：失败后可能出现二次兜底弹窗IPCheckTask 自己显示原因弹窗并退出，随后抛出 TokenClientBlockedException；GameMode_Loading 的外层捕获会继续显示 HTTPNetworkProblem。在某些平台上可能看到二次日志、二次弹窗或重复 Quit。
低：允许结果的日志字段不准确AuthResult.Allowed() 没有把 HasServerResponse 设为 true，所以成功时日志可能显示“有服务端响应=false”，但不影响实际 allow 判断。

六、建议的最小联调顺序

为要测试的目标平台保留 BIZZA_REAL_WITHDRAW + BIZZA_IPINTERCEPT，确认移除 DEBUG_MODE，或临时调整 GameMode_Loading.cs 的条件。
在 Bizza → Channel Config 中确认 AppId 非空，保存生成 Assets/StreamingAssets/ChannelConfig.bytes，并确认 Worker 使用同一个 AppId。
先检查日志是否出现 [令牌客户端] 启动流程开始；没有这行时，不要继续排查服务器 IP 规则。
编辑器测试先将 UseEditorMockDeviceInfo=true，用 Editor...=CN 或 EditorIsVpnConnected=true 验证不同 publicReason 的 UI 分支。
真机测试确认 Android Java 类 com.bangsawan.oceanshine.DeviceUtils 和 Google ID 回调链路有效，再核对 Worker 侧 requestId、源 IP、appId、packageName 和 allow 结果。
若出现 SERVER_ERROR，按顺序排查：宏是否真正挂任务 → ChannelConfig.Instance 是否已加载 → HTTPS/域名可达 → 响应是否为合法 JSON。
